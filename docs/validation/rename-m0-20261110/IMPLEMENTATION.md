# ra9fael.rename 实施验证（M1–M5）

[English](IMPLEMENTATION.en.md)

日期：2026-11-10。覆盖 M1（纯核心）、M2（Windows 适配）、M3/M4（界面层）、M5（元数据 + 收尾）。**M0 的六条宿主假设仍未验证**，见 [M0 验证](README.md)。

## 1. 问题是什么

M0 只立起了骨架，六条关键假设一条都没测。本阶段要做的是把设计里能自证的部分全部实现并测掉——规则核心、执行器、双模式界面逻辑——同时把不能自证的部分（宿主往返、Qt 窗口、提权提示）明确留成"未验证"。

环境：Windows x64、MSVC 19.51.36260.0、CMake 3.29.2、Ninja、PowerShell 7。**本机未安装 Qt**（无 `Qt6Config.cmake`、无 `Qt6Core.dll`、无 vcpkg），所以 Qt 窗口只能作为可选目标交付。

## 2. 为什么

设计里有一段是可以完全自证的：给定规则和文件名，最终名字应该是确定的；给定一个批次，执行顺序应该是确定的；给定一个冲突，应该拒绝。这些不需要宿主、不需要 Qt、不需要真机，纯逻辑就能证明。先把这段做实，剩下的不确定性才小。

反过来，`IFileOperation` 能否在插件进程里改名、宿主 `files` 触发是否真的送达、Qt 共享契约是否可用——这三件**必须**有宿主环境才能测，所以本阶段不假装完成。

## 4. 实测

| 项 | 方法 | 结果 |
|---|---|---|
| 构建 | Ninja + MSVC 19.51，`/W4 /permissive-` | 通过，**零 error 零 warning** |
| L1 纯核心 | `ctest` → `rename_core` | **85/85 通过** |
| L2/L3 端到端 | `ctest` → `rename_e2e` | **14/14 断言通过**，真实改名落盘 |
| 架构门禁 | `ctest` → `core_purity` | 通过；负例验证过（插 `#include <windows.h>` 会被拦并报行列） |
| Qt 关闭路径 | `cmake -DRENAME_BUILD_QT=OFF`（默认） | 配置+构建通过，输出 `RENAME_BUILD_QT=OFF` 提示 |

证据：`ctest-implementation.txt`（完整输出）、`e2e-rename.txt`（真实改名日志）。

### 4.1 端到端证明了什么

`e2e-rename.exe` 在临时目录里真实执行，14 条断言逐一通过：

- 枚举拿到两项、未被阻断
- 计划把两行都标为 `ready`
- **磁盘上两个文件真的改名了**，原名消失
- 目标已存在时**拒绝**，原目标未被动，源文件未改名，且**没有生成 `taken (1).txt`**——这是防止抄到 PowerRename 的 `FOF_RENAMEONCOLLISION` 行为的直接证据
- 父目录与子文件同批改名时，**子项先改、父项后改**，最终子文件在新父目录下

### 4.2 测试抓到并修掉的 10 个实现 bug

全部是实现错误，不是设计问题，每一条都被用例当场拦下：

| # | Bug | 后果 | 修法 |
|---|---|---|---|
| 1 | `FormatCounter` 格式串写成 `"%%ll"` | 所有计数返回**空字符串** | 改为 `"%lld"` / `"%0<width>lld"` |
| 2 | Title Case 把 `don't` 切成两个词 | 输出 `Don'T` | 撇号只在词首/分隔符后算边界 |
| 3 | `Capitalize` 同源问题 | 同上 | 一并修正 |
| 4 | oil 解析器先查路径分隔符、后剥尾部斜杠 | 目录行 `/1044 photos/` 被判为非法路径 | 调整顺序：链接 → 剥斜杠 → 查内部分隔符 |
| 5 | 链接 `-> ` 检查晚于分隔符检查 | 链接行报错类型错误 | 链接检查提到最前 |
| 6 | 计数器从 0 开始编号 | 用户看到 `pic-0` | `value` 初值改为 `start`（默认 1） |
| 7 | 批量冲突只标记一行 | 另一行仍显示 `ready`，会漏报 | 两段式：先快照 `Ready` 再统一标记 |
| 8 | `Rebuild()` 先重建再恢复选中 | 选中的 `m_rows` 已被清空，勾选丢失 | 重建**前**快照选中状态 |
| 9 | `$DATE_TAKEN` 被 `$D` 吃掉 | 元数据键 `DATE_TAKEN` 无法展开 | 负向前瞻补上无下划线变体 |
| 10 | CRT 混用（静态 exe + 动态静态库） | LNK2038 | 所有目标统一 `MultiThreaded` |

## 5. 没测的

**这一节不省略。**

### 5.1 宿主相关：一条都没测

- `files` 触发**从未在真实宿主里触发过**。`main.cpp` 能编译、能服务协议，但从未装上、从未点过右键菜单。
- `files` 数组 32000 字符上限的真实行为未知。
- 共享 Qt 契约（`runtime.qt: "host"`）**完全没有验证**，因为本机没有 Qt。
- `IFileOperation` 的提权提示（`FOFX_SHOWELEVATIONPROMPT`）在插件进程中的实际呈现未知。
- 权限声明 `ui` / `files:read` / `files:write` 只做了 schema 对照，未在真实宿主里走同意流程。

### 5.2 Qt 窗口：写完了但从未编译过

`ui/bridge.cpp`、`ui/qml/Main.qml`、`ui/window_main.cpp` 一行都没编译过——本机无 Qt。它们**可能包含编译错误**。`RENAME_BUILD_QT=ON` 是唯一入口，启用前必须先装 Qt 6.5+。

QML 里的单规则编辑器只有一个规则行，规则链编辑、标志位面板、`/<id>` 只读前缀、行号槽都还是 M5 之后的活。

### 5.3 明确未验证的行为

- **身份复核的边界**：`execute.cpp` 比较大小/时间/卷序列/文件索引，但"同尺寸同时间戳的替换"无法识别。这是已知限制，未做对抗测试。
- **SMB**：一次都没在共享上跑过。断线、`IFileOperation` 语义差异、临时名行为全部未知。
- **撤销**：`FOF_ALLOWUNDO | FOFX_ADDUNDORECORD` 已设置，但**从未验证过 Ctrl+Z 真的能撤销**。
- **交换名与仅大小写改名**：`IFileOperation` 的实测行为未知。
- **元数据**：`metadata.cpp` 用 WIC 读 EXIF，但**没有测试图片**，一条元数据断言都没有端到端跑过。只有模板展开的单元测试（用注入的 map）。
- **递归收集**：`Enumerate` 的递归分支从未执行过（`main.cpp` 传 `recursive = false`，e2e 也只测平铺）。
- **x86 拒绝**：只写了 `CMAKE_SIZEOF_VOID_P` 检查，未实际尝试 32 位配置。
- **无障碍、DPI、主题**：全部未测，因为窗口没跑起来。

## 6. 结论

**可以宣称的**：规则核心、冲突拒绝、深度倒序执行、双模式状态一致性、oil 解析与差异，全部有可复现的自动化证据。

**不能宣称的**：插件在真实宿主里能用。入口、权限、Qt 窗口、提权、撤销、SMB、元数据、递归——这八项一条都没实测。

下一步必须是有宿主环境的人跑 P1：装上 `rename.exe`，从结果菜单触发一次，看 stderr 有没有 `files` 载荷。在那之前，"能改名"只对临时目录成立。
