# Rename：结果菜单与关键词搜索集成方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

Rename 已声明文件和文件夹结果右键入口，复杂规则、批量工作和文本编辑也已集中在独立工作窗口。现有分工适合继续保留。

本轮做两件事：给已有菜单入口增加显示开关，验证选择集准确传入窗口；让关键词入口不再只能开空窗口——搜索框本身就是 Win顺 的搜索界面，关键词后面的词应当交给宿主的文件名索引。当前只有一个简单偏好，无需新增专用设置窗口。

## 界面方案

- 关键词入口（`br`/`pl`/`rename`/批量重命名）：后面接着打名字就在 Win顺 的索引里按文件名搜索。第一行“批量重命名匹配的 N 项…”打开窗口改全部匹配，后面几行各打开一个文件；留空回车仍是空窗口。在某个文件夹里搜索时的“在此文件夹批量重命名…”保持原样，打开该文件夹的直接子项。
- 文件和文件夹结果保留“批量重命名…”，窗口的输入集就是选中的这些项目。
- 宿主卡片增加默认开启的“在文件结果右键菜单显示重命名”。
- 规则链、文本模式、冲突、预览和批量执行继续放在现有窗口。

菜单开关只影响右键入口，关闭后关键词仍可使用。

## 实现方案

1. 保留现有 SDK 头文件与协议：`query`、`action` 与 `files` 解析不变，只新增对 `winshun/tool` 的 `search_files` 调用。
2. 在 `package/plugin.json` 声明宿主管理的布尔项，现有 `triggers.files.if` 引用该键；清单新增 `winshun:search` 权限（更新到本版时用户在插件卡片上确认）。
3. 保留已有选择上限和文件／文件夹类型。单选也是输入集：一个文件是一行批次，一个文件夹改的是它自己，不替换成父目录扫描或文件夹内容；文件夹内容走“在此文件夹”入口。
4. 关键词搜索在 `query()` 里做：`tool()` 只能在协议线程调用，而 `query()` 就在那条线程上，因此不需要额外的线程或队列。结果转成纯 C++ 的行（`ui/search_rows.*`），协议无关、可单测；一行携带 `data.openPaths`（全部匹配）或 `data.openPath`（单个文件），`action()` 据此开窗。
5. 查询和开窗不执行改名，继续通过已有预览及执行确认流程落盘。
6. `if` 在旧宿主会被忽略，因此 `minWinShun` 定为 0.33.0；`tools/check-manifest.ps1` 把布尔项、默认开启、`files.if` 引用、这个下限以及“用到 `search_files` 就必须声明 `winshun:search`”做成门禁（ctest `manifest_menu_switch`），负例用临时清单判失败。
7. 选择集中有读不到的路径时不装载半批：枚举返回空集，窗口显示原因并禁止执行。窗口侧原本就丢弃了阻塞批次的行，这条补的是枚举自身的约定和一条 e2e 断言。
8. 跨目录批次：批内同名与“目标被别的行占着”改按目录判断（`core/plan.cpp`、`core/oil_differ.cpp`），不同目录的同名文件既不冲突也不互相等待；窗口在批次跨目录时把每行自己的目录显示在原始列（悬停给完整路径），单目录批次保持原样。

不声明 `settingsWindow`；独立工作窗口继续是重命名任务界面。

## 验收标准

- 支持该能力的宿主默认显示菜单，关闭设置后隐藏。
- 菜单隐藏时关键词仍能使用。
- 关键词后打名字能列出匹配项；首行打开窗口且输入集就是这些匹配（跨目录也算），文件行只打开那一个；没有匹配时给出说明行。
- 单选和多选准确传入选中路径；当前文件夹入口遵循原语义。
- 选中路径里有读不到的项时不装载半批：窗口为空、显示原因、不能执行。
- 查询和开窗不修改文件，执行阶段才改名。
- 使用临时文件运行相关清单、动作 payload、搜索行和重命名集成验证。
