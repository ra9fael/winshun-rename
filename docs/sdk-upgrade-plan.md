# Rename：结果菜单与目录导航改进方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

Rename 已声明文件和文件夹结果右键入口，复杂规则、批量工作和文本编辑也已集中在独立工作窗口。现有分工适合继续保留。

本轮给已有菜单入口增加显示开关，验证选择集准确传入窗口，并修掉切目录时丢掉文本 tab 的问题。当前只有一个简单偏好，无需新增专用设置窗口。

## 界面方案

- 关键词入口（`br`/`pl`/`rename`/批量重命名）回车打开空窗口；在某个文件夹里搜索时的“在此文件夹批量重命名…”打开该文件夹的直接子项。
- 文件和文件夹结果保留“批量重命名…”，窗口的输入集就是选中的这些项目。
- 宿主卡片增加默认开启的“在文件结果右键菜单显示重命名”。
- 窗口的规则 tab / 文本 tab 是用户的选择：回到上一级、刷新、换文件夹都保留它，缓冲区按新目录重建。
- 规则链、文本模式、冲突、预览和批量执行继续放在现有窗口。

菜单开关只影响右键入口，关闭后关键词仍可使用。

## 实现方案

1. 保留现有 SDK 头文件与协议：`query`、`action` 与 `files` 解析都不变，插件不调用宿主的工具。
2. 在 `package/plugin.json` 声明宿主管理的布尔项，现有 `triggers.files.if` 引用该键。
3. 保留已有选择上限和文件／文件夹类型。单选也是输入集：一个文件是一行批次，一个文件夹改的是它自己，不替换成父目录扫描或文件夹内容；文件夹内容走“在此文件夹”入口。
4. 导航不重置模式：`Bridge::setFolder` 记下当前是否在文本模式，重新枚举并替换输入集后恢复该模式，并用新目录的项目重建 oil 表（旧缓冲区描述的是旧集合）。枚举失败时同样保留 tab，只显示空状态和原因。
5. 查询和开窗不执行改名，继续通过已有预览及执行确认流程落盘。
6. `if` 在旧宿主会被忽略，因此 `minWinShun` 定为 0.33.0；`tools/check-manifest.ps1` 把布尔项、默认开启、`files.if` 引用与这个下限做成门禁（ctest `manifest_menu_switch`），负例用临时清单判失败。
7. 选择集中有读不到的路径时不装载半批：枚举返回空集，窗口显示原因并禁止执行。窗口侧原本就丢弃了阻塞批次的行，这条补的是枚举自身的约定和一条 e2e 断言。
8. 跨目录批次：批内同名与“目标被别的行占着”改按目录判断（`core/plan.cpp`、`core/oil_differ.cpp`），不同目录的同名文件既不冲突也不互相等待；窗口在批次跨目录时把每行自己的目录显示在原始列（悬停给完整路径），单目录批次保持原样。

不声明 `settingsWindow`；独立工作窗口继续是重命名任务界面。

## 验收标准

- 支持该能力的宿主默认显示菜单，关闭设置后隐藏。
- 菜单隐藏时关键词仍能使用。
- 单选和多选准确传入选中路径；当前文件夹入口遵循原语义。
- 在文本 tab 上回到上一级、刷新或换文件夹后仍在文本 tab，缓冲区是新目录的直接子项。
- 选中路径里有读不到的项时不装载半批：窗口为空、显示原因、不能执行。
- 查询和开窗不修改文件，执行阶段才改名。
- 使用临时文件运行相关清单、动作 payload、目录导航和重命名集成验证。
